# Train E4 on Kaggle

Attach the [BraTS 2021 Task 1 dataset](https://www.kaggle.com/datasets/dschettler8845/brats-2021-task1), enable Internet, and choose a single GPU. Keep the same dataset version and GPU type across sessions. The runner accepts subject folders or a mounted training tar. It uses scratch space to stage the NIfTI files and build healthy-slice LMDBs. A full run needs room for the staged training files and resized slices. It rebuilds and fingerprints both LMDBs in each fresh session.

In Kaggle Secrets, add `WANDB_API_KEY` for the private [E4 W&B project](https://forge.coreweave.com/wandb/ahmad-abbas176/andi-e4/workspace) and grant the notebook access. For another deployment, set the endpoint, entity, and project accordingly.

## Copy this cell into a Kaggle notebook

Start with `SMOKE = True`. It uses the first eight healthy slices of the first training subject, runs four optimizer steps, and compares a saved-and-reloaded mid-epoch update against the uninterrupted update. The comparison covers model, EMA, optimizer, scheduler, cursor and RNG. It includes an upload, fresh remote download, selection on a tiny validation subset, and a final verified checkpoint.

```python
import os
import subprocess
import sys
from pathlib import Path
from tempfile import TemporaryDirectory
from uuid import uuid4

from kaggle_secrets import UserSecretsClient

SMOKE = True
VARIANT = "consistency"  # "baseline", "augmentation", or "consistency"
CONSISTENCY_LAMBDA = 0.1
EPOCHS = 232
BATCH_SIZE = 128  # Effective healthy slices per optimizer update.
MICROBATCH_SIZE = 2  # Slices processed together on the GPU.
INITIALIZE_PRETRAINED = False
RESUME = None  # e.g. "ahmad-abbas176/andi-e4/e4-consistency-a1b2c3d4:verified"
COMMIT = None  # Use the printed full commit SHA when resuming.

ENTITY = "ahmad-abbas176"
PROJECT = "andi-e4"
BASE_URL = "https://api.forge.coreweave.com"
BRANCH = "codex/e4-kaggle-training"
env = os.environ | {
    "WANDB_API_KEY": UserSecretsClient().get_secret("WANDB_API_KEY"),
    "WANDB_BASE_URL": BASE_URL,
    "CUBLAS_WORKSPACE_CONFIG": ":4096:8",
    "MPLBACKEND": "Agg",
}
if RESUME:
    if INITIALIZE_PRETRAINED or not COMMIT:
        raise ValueError("Resume requires the original COMMIT and INITIALIZE_PRETRAINED=False")
    collection = RESUME.rsplit("/", 1)[-1].split(":", 1)[0]
else:
    mode = "smoke" if SMOKE else VARIANT
    collection = f"e4-{mode}-{uuid4().hex[:8]}"

print(f"Recovery reference = {ENTITY}/{PROJECT}/{collection}:verified", flush=True)
subprocess.run([sys.executable, "-m", "pip", "install", "wandb==0.31.0"], check=True)
with TemporaryDirectory() as work:
    repo = Path(work) / "ANDi"
    subprocess.run(
        ["git", "clone", "--single-branch", "--branch", BRANCH,
         "https://github.com/ahmad-m-abbas/ANDi.git", str(repo)],
        check=True,
    )
    if COMMIT:
        subprocess.run(["git", "checkout", "--detach", COMMIT], cwd=repo, check=True)
    commit = subprocess.check_output(["git", "rev-parse", "HEAD"], cwd=repo, text=True).strip()
    print(f"COMMIT = {commit!r}", flush=True)
    cmd = [
        sys.executable, "-u", "kaggle/e4_one_cell.py",
        "--entity", ENTITY, "--project", PROJECT, "--collection", collection,
        "--variant", VARIANT, "--consistency-lambda", str(CONSISTENCY_LAMBDA),
        "--epochs", str(EPOCHS), "--batch-size", str(BATCH_SIZE),
        "--microbatch-size", str(MICROBATCH_SIZE),
        "--save-steps", "500", "--save-seconds", "600",
    ]
    if SMOKE:
        cmd.append("--smoke")
    if INITIALIZE_PRETRAINED:
        cmd.append("--initialize")
    if RESUME:
        cmd.extend(["--resume", RESUME])
    subprocess.run(cmd, cwd=repo, env=env, check=True)
```

## Run and compare

- **Fresh** starts a U-Net from the recorded initialization seed. Set `SMOKE = False` to train on all eligible healthy slices in `splits/BraTS21/scans_train.csv`. The default budget is 232 epochs and 128 healthy slices per optimizer update, as reported in Appendix A of the [ANDi paper](https://arxiv.org/pdf/2312.01904#page=11). The runner accumulates gradients from microbatches of two on one GPU. It draws the pyramidal noise for the full batch and advances AdamW, the scheduler, and EMA once per optimizer update. The last batch of each epoch can be smaller. The model, diffusion, learning rate, and EMA settings come from `conf/train.yml`, whose legacy epoch count is 233.
- **Pretrained initialization** sets `INITIALIZE_PRETRAINED = True` and mounts [Kaggle Model version 1](https://www.kaggle.com/models/ahmadabbas176/232-ema-ckpt-pt/PyTorch/default/1). The runner checks the published `232_ema_ckpt.pt` SHA-256 and loads it strictly into both the starting model and EMA. Optimizer, scheduler, EMA counter, and batch cursor start fresh.
- **Exact resume** sets `RESUME` to the printed `:verified` reference or an immutable verified `:vN` from the same collection. Set `COMMIT` to the printed source commit and keep the original training settings and runtime. One active writer per collection. A resumed Kaggle session creates a new W&B run in the same artifact collection. The checkpoint restores training state, and the new run logs its starting artifact reference and continues with the restored global step.

After smoke, submit one fresh background run per variant: `baseline`, `augmentation`, and `consistency`. Use the same initialization, seeds, budget, microbatch size, and pinned commit for all three. Use the released ANDi checkpoint as an additional frozen reference. If you only need to isolate the effect of the consistency term, the matched `augmentation` and `consistency` pair answers that comparison. Baseline uses the original single-view DDPM objective. Augmentation uses both views and sets the consistency weight to zero. Consistency uses background-preserving per-slice, per-modality gamma in `[0.85, 1.15]` and adds the weighted prediction MSE between views. Paired views use the same timestep and pyramidal noise. For a predeclared first sweep, use weights `0.01`, `0.1`, and `0.3`, each in its own collection. Loss components are logged by global step.

Each epoch scores the EMA on unchanged healthy slices from `scans_val.csv` with identical validation seeds and noise across matched runs. Select the lowest fixed-noise validation MSE. This training-side criterion measures denoising. Held-out anomaly metrics and scanner-shift evaluation are separate follow-up experiments. The cell never stages the test split. It writes the selection and a plain `selected_ema_ckpt.pt` compatible with existing ANDi evaluators. The selected EMA is also recoverable as the `ema_model` field in the selected W&B artifact.

## Recover after a session ends

A fresh run writes a step-zero checkpoint before training. It writes new versions after every 500 optimizer steps or ten minutes, whichever comes first at a completed step, and at epoch and final boundaries. It saves model, EMA and its update counter, optimizer, scheduler, cursor, best validation selection, configuration, dataset fingerprints, seeds, and RNG states. Local writes use an atomic rename after flushing. The runner then waits for W&B, downloads the version into a fresh directory, compares SHA-256, and advances `:verified`. `:best` and `:final` identify validation selection and completion. Use verified versions for recovery.

On upload failure the runner retries twice. If all attempts fail it stops and leaves the new local snapshot and earlier local snapshots intact. It retains two recent local snapshots plus the local validation selection after successful verification. Remote versions are retained. Recovery after Kaggle reclaims the workspace uses the last verified remote version.

An interruption can lose work since the last successful upload, including an in-progress optimizer step or validation pass. Upload and validation take extra time beyond the step or time interval. Mid-epoch recovery resumes at the next optimizer batch. An interruption during gradient accumulation replays that batch from the last verified cursor. An interrupted validation pass is repeated when the recovered cursor is at the end of an epoch. Exact replay uses the same pinned source, prepared data, configuration, and compatible GPU/software. Hardware or software changes can prevent bitwise replay.

On a Slurm compute node without Git, pass `--source-commit "$(git rev-parse HEAD)"` as a script argument to `sbatch` from the pinned checkout on the login node. Forward it to the E4 runner with `"$@"` in your job script. The runner records the supplied SHA in its checkpoint configuration.

For Slurm jobs with persistent storage, add `--filesystem-checkpoints` and set `--output` to a directory accessible from future allocations. W&B logs metrics while the numbered checkpoints and `best.pt` stay under the session's `checkpoints/` directory. Keep the latest numbered checkpoint and its sibling `best.pt`. To continue, pass `--filesystem-checkpoints --resume-local /path/to/latest-numbered-checkpoint.pt` with the same source commit, settings, data, and GPU environment. The new session copies across the previous validation selection and creates its own output directory. Keep prior session files until a newer session has produced a checkpoint.

The temporary LMDB uses Python's temporary directory. Set `TMPDIR` to a writable directory with sufficient space before launching. Prefer node-local scratch for the LMDB and persistent storage for `--output`.

Local checks can run against an extracted BraTS21 root with `--smoke --local-only --collection local-smoke --data <path> --output <path>`. Focused checks run with `python -m unittest discover -s tests -v`. Verification covered CPU replay on real healthy slices and W&B transfer and recovery of synthetic snapshots. Kaggle GPU execution, full training, and external evaluation remain unverified.
